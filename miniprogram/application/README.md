# 应用层

`service.ts` 统一项目与记录命令、修订冲突、稳定 ID 重试、新增配置草稿和有绝对期限的撤销。页面在仓储确认提交后才显示成功。`presentation.ts` 统一单位和指标顺序；`query.ts` 按日期/保存时间/ID 稳定游标分页。

`record-fields.ts` 构建面板的一次性字段快照，保留原始整秒、历史空项和滑轨范围；数值与日期摘要复用 `presentation.ts`，不另存展示用总数。`project-form.ts` 只准备配置候选，实际写入仍由命令层验证。页面生命周期与原生输入事件留在页面/组件，不通过应用层另建状态容器。

`service()` 惰性初始化微信平台；纯领域和仓储测试可在无 wx 的 Node 环境运行。`prepare()` 遇损坏回落时说明可能缺少最近修改，确认前保持只读。

`prepare()` 先调用 `initialize()`：通过 `initial-data.ts` 为无存档的新用户一次性生成阅读、跳绳、运动及含当天的七天模拟记录，原子写入后再展示。已有存档或删除标记不追加；普通 `snapshot()` 不触发初始化。详见[首次使用初始化方案](../../docs/product/首次使用初始化.md)。
