# 基础设施层

`WechatFiles` 业务读写仅访问 `USER_DATA_PATH/polaris/v1/`，路径不接受项目名或备注。只把明确的文件不存在当成空库，权限与其他 IO 错误保留为错误。

`polaris` 是北极星的英文存储标识。首次访问时，若新命名空间不存在而旧 `yugong` 存在，整体重命名旧目录，保留项目、记录、草稿、撤销及删除标记；迁移失败停止读写并允许重试。两目录同时存在时只使用 `polaris`，不覆盖或自动合并。该迁移需继续在微信真机验证。

`LocalRepository` 提供串行事务、不可变分片、双清单校验与回读。记录按项目/月分片，页目标 120KiB；草稿与撤销元数据随清单提交，避免跨存储事务。删除先确认标记，禁止旧清单或迟到命令复活项目。初始软容量 120MiB，不足时拒绝写入，不自动删历史。

`repository.ts` 只协调队列、恢复和原子发布；`file-codec.ts` 独立维护既有清单/封装格式、UTF-8字节计数与校验和；`database-validation.ts` 在读取和提交时复用同一快照校验。模块拆分不升级schema、不改文件路径或序列化规则。

当前快照在内存中保留整库，提交重新分桶并检查文件引用。分片持久化与 UI 分页已实现，磁盘按需加载及大容量真机性能尚未验收。

`initializeNewUser()` 与普通事务共享串行队列，仅在无已提交清单且无删除标记时写入初始卡片和记录。第一份清单同时确认初始化完成，不独立写KV标记；删光项目后不重建。纯快照读取不生成数据，损坏清单与IO失败也不降级为空库。规则见[首次使用初始化方案](../../docs/product/首次使用初始化.md)。
