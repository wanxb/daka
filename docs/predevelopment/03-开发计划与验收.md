## 4. 统计测试向量

[acceptance-cases.json](acceptance-cases.json)保存固定输入与人工定义的期望结果，用来约束正式版算法。向量的自检只能证明样例自洽，不能冒充正式版测试通过。

必须覆盖：时间单项、数量单项、双项缺失、周/月/年基数、历史补记、修改、删除撤销、模式变化、年界与闰日。命令级另测重复提交、失效revision与被删除项目。

随机性质测试应验证：追加有效记录后的总量增量等于该记录、相同记录集合聚合不受输入顺序影响、累计在无负值时单调不减、删除并撤销回到原结果、修改等于减旧加新。不要写只复述函数内部步骤的测试。

## 5. 数据恢复测试

对写新页、回读、项目索引、非当前清单写入、清单回读、UI成功反馈、垃圾回收等阶段分别注入失败与进程中断。

核对：已确认记录不重复；未发布页不进入统计；重试使用同一身份；旧版本保留；损坏不触发清空；项目删除标记优先；缓存能重建；没有未经确认的成功提示。

异常包括文件配额、设备空间不足、半写文件、未知schemaVersion、过期记录revision、撤销期限跨后台、回调到达时项目已删除。内部恢复不宣称覆盖系统清除数据或无备份的硬件损坏。

## 6. 布局与真机矩阵

| 维度 | 至少验证 |
|---|---|
| 屏宽 | 375、390、430逻辑像素；横屏或宽屏保持可用 |
| 内容 | 24字符项目名、10000小时、超大数量、500字符备注、只知一项 |
| 系统 | iPhone和Android的实际微信版本与基础库记录在报告中 |
| 输入 | 数字键盘、日期/时分选择器、键盘顶起、备注焦点、收起与返回 |
| 手势 | 横向尺与纵向面板不抢手势，快速拖动不抖动、不提交 |
| 无障碍 | 较大字体、读屏名称、方向调整、减少动效、对比度 |
| 数据量 | 100/10000/100000条不同备注长度，均注明实际字节与机型 |
| 生命周期 | 冷启、热启、后台、杀进程、版本升级、当天跨午夜 |

性能起始目标：按压反馈100毫秒内可见；常规本地记录提交争取200毫秒内；首屏和详情避免阻塞主线程长任务；滚动与拖动以稳定60fps体验为目标。这些是测量预算，尚未取得真机结果。

数据量大的列表必须分页；启动不一次setData所有记录；图表先聚合再绘制。达到预算后不为跑分增加框架或服务器。

## 7. 微信环境与发布准备

当前本机CLI文件存在：D:/Tencent/微信web开发者工具/wechatide.cmd。短命令不在PATH时使用完整路径，不需要重复安装已存在工具。

小程序本身的备案与服务器域名备案是不同事项。首版无业务网络接口，不为它购买服务器或域名；小程序账号认证、备案、审核仍按 [已有上架调研](../../小程序上架准备与技能选型调研-20261124.md) 准备，费用以下单页面为准。

时间单位验收补充：1时记录切为60分、3600秒；追加1分和1秒后原始累计为3661秒。再切小时仅改变显示，编辑1秒记录的备注不得改写其秒数。范围0～10默认5，手动60结束编辑后限制为10；数量初始1～100、默认50。
